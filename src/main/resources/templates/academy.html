Technical guide

Bitcoin building blocks

Drag cards to arrange your reading path

Blocks, hashes & Proof of Work

Transactions are grouped into blocks. Each block commits to its contents and its parent, forming a chain that is expensive to rewrite.

Technical deep dive

Miners vary a nonce and hash a block header with double SHA-256 until the result is below the network's difficulty target. Nodes independently validate the proof and every consensus rule.

UTXOs & transaction flow

Bitcoin does not keep a simple account balance. Wallets track unspent transaction outputs (UTXOs) that can be used as inputs to a new transaction.

Technical deep dive

An output is identified by its transaction ID and output index (outpoint). Inputs spend previous outputs; new outputs assign value to spending conditions. The difference between inputs and outputs is the fee.

Mempool, fees & confirmation

Unconfirmed transactions wait in node mempools. Miners generally prioritize transactions by fee rate, measured in satoshis per virtual byte (sat/vB).

Technical deep dive

A fee estimator is a snapshot, not a promise: demand changes, nodes can have different mempools, and confirmation time is uncertain. A block confirmation means the transaction is included in that block.

Nodes & consensus

Full nodes download and verify blocks and transactions against Bitcoin's rules. Mining proposes blocks; node validation decides whether those blocks are acceptable.

Technical deep dive

Nodes follow the valid chain with the most accumulated proof of work. They do not blindly trust a miner: invalid transactions or blocks are rejected, even if they contain substantial work.

Halving & issuance

The block subsidy decreases by half every 210,000 blocks. This changes new issuance; it does not guarantee a particular market price or outcome.

Technical deep dive

Subsidy is determined by block height using integer satoshis. Transaction fees are separate and are also collected by the miner. The subsidy eventually rounds down to zero.

Keys, scripts & self-custody

A private key authorizes spending. Bitcoin outputs use locking conditions (scripts); a wallet manages keys and helps create transactions that satisfy those conditions.

Technical deep dive

A seed phrase can regenerate wallet keys and must be kept offline and private. A public address is not a password; sharing a seed phrase or signing an unknown transaction can put funds at risk.

Bitcoin vs. tokens & memecoins

Bitcoin has its own consensus network and a maximum issuance of 21 million BTC. Other tokens can use different chains, contracts, governance and supply rules.

Technical deep dive

"Memecoin" describes a broad category, not one shared token design. Supply, upgrade controls, liquidity and security depend on the specific project; check its contract and chain rather than assuming a common rule.

How Ethereum differs

Ethereum is a programmable blockchain whose execution layer runs smart contracts. Ether pays for computation and helps secure the network through proof of stake.

Technical deep dive

Bitcoin Script is intentionally limited, while Ethereum's virtual machine executes general-purpose smart-contract bytecode. Both systems have tradeoffs in design, trust assumptions and application scope.
